# Development

`SPDX-License-Identifier: AGPL-3.0-only`

VMPacker is currently a development-stage macOS ARM64 CLI project. It is not release-ready. The Go module path remains the repository placeholder until a canonical public path is selected.

## Prerequisites

- macOS on Apple silicon.
- Go 1.21 or newer.
- Python 3.
- Android NDK revision 29.0.14206865 exactly, with its AArch64 API 23+ Clang toolchain.

Confirm the NDK before building:

```sh
awk -F= '$1 ~ /^[[:space:]]*Pkg.Revision[[:space:]]*$/ { print $2 }' "$ANDROID_NDK/source.properties"
```

The trimmed value must be `29.0.14206865`.

## Repository checks

```sh
make android-stub ANDROID_NDK=/path/to/android-ndk-r29
make packer ANDROID_NDK=/path/to/android-ndk-r29
go list ./...
go test -count=1 ./...
go vet ./cmd/vmpacker ./internal/...
go build ./cmd/vmpacker
bash -n scripts/*.sh
bash scripts/check-contract.sh
```

The default contract check covers completed Phase 0-2 product-scope and application-boundary work. Release readiness is stricter:

```sh
bash scripts/check-contract.sh --release
```

Release mode is expected to report the fixed `cmd/vmpacker/vm_interp.bin` embedding as a deferred Phase 4 blocker until the later runtime-template phase removes it.

## Current build

```sh
make android-stub ANDROID_NDK=/path/to/android-ndk-r29
make mac-cli ANDROID_NDK=/path/to/android-ndk-r29
```

The selected NDK's `source.properties` must contain revision 29.0.14206865. The resulting development CLI is `dist/vmpacker-darwin-arm64` with `dist/vmpacker` as the direct runner. The fixed embedded interpreter blob is retained only to keep the existing build functional during Phase 0-1; it is not release-compliant.

Independent fixtures remain under `testdata/android/`. Active host/native smoke entry points are:

```sh
make android-fixtures ANDROID_NDK=/path/to/android-ndk-r29
make mac-so-pack-smoke ANDROID_NDK=/path/to/android-ndk-r29
make android-native-smoke ANDROID_NDK=/path/to/android-ndk-r29
```

The archived APK and GUI snapshots are unsupported and have isolated Go modules so root traversal excludes them.

## Approved target contract

The authoritative complete target contract is [product-contract.md](product-contract.md). The following is only its Phase 0 summary, not a claim of current implementation or passing status.

- Input ELF size is at most 1 GiB, generated bytecode is at most 64 KiB per protected function, and one invocation protects at most 4096 functions.
- The entry ABI accepts at most 8 integer or pointer arguments and returns either `void` or one integer or pointer value. Handling of other entry ABIs is fail-closed.
- Production randomness defaults to `crypto/rand`. An explicit seed is for debug/test only and is never reported.
- Input, output, and report paths are distinct. The default is no-clobber; `-force` uses atomic same-directory temporary-file replacement.
- Unsupported instructions, malformed or ambiguous CFGs, and invalid or unsupported ELF inputs use fail-closed handling without partial-success output.
- Report v1 has `schema_version: 1` and is emitted by the Phase 2 application boundary with `release_ready: false` while later gates remain incomplete.

## Physical-device gates

Release claims require reproducible physical-device load and execution checks for API 23+, 4 KiB and 16 KiB page sizes, BTI, PAC, dynamic-linker behavior, and transformed entry/return behavior. These gates are not currently claimed as passing.

The workflow retains `macos-14-xlarge` because this repository does not yet document entitlement to a standard macOS ARM64 runner label. Moving to another label is blocked until that runner availability is documented for this repository.

## Scope discipline

Do not publish artifacts from CI. Do not describe 16 KiB pages, BTI, PAC, API coverage, or device compatibility as passing until a reproducible gate demonstrates it. Runtime and ELF semantic redesign belongs to later phases.
